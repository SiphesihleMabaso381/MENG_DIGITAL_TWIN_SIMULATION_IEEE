Proposed framework for NTL detection

Simple architectural implementation:
Multi-Agent Federated Physics-Informed Digital Twin Framework for Explainable NTL Detection

Current implementation boundary:
The project currently provides a synthetic IEEE-benchmark foundation for this proposed framework. It includes OpenDSS feeder simulation, hybrid metering, NTL and operational-event injection, data-quality checks, physics-informed checks, lightweight explainability, federated-learning scaffolding, and deployment-readiness reporting. A final trained AI detector and live utility decision system are not part of the current phase.

Main idea:
Build a new NTL detection system that is not only based on AI prediction, but also uses several intelligent agents to check data, physics, digital-twin behaviour, and explainability before making a final decision.

The core thinking:
Instead of saying a model is suspicious, the system should explain why it is suspicious and whether that explanation is physically realistic.

Main components:
1. Local Data Agent
   - Reads the current synthetic feeder and customer data locally.
   - Collects consumption behaviour, meter status, time trends, and operational context.
   - Uses the current data-quality module to prepare clean inputs for the rest of the framework.

2. Physics Agent
   - Checks whether the observed pattern is physically possible.
   - Uses power-flow logic, voltage behaviour, feeder topology, and network constraints.
   - The current physics-informed module performs basic feeder power-balance and voltage-plausibility checks.
   - A future detector can use these checks to reject unrealistic alerts caused by noise or poor data.

3. Anomaly Agent
   - This is currently a proposed research component, not a trained production model.
   - The simulator already generates NTL events and labeling-ready synthetic data for developing and comparing detection methods.
   - Future baseline or AI methods can find unusual consumption, temporal, and pattern-based deviations.

4. Explainability Agent
   - Explains the reason for the alert.
   - Shows the evidence used to reach the decision, such as abnormal usage patterns, physical inconsistency, or simulation support.
   - The current ExplainabilityEngine provides lightweight feature-importance and anomaly explanations.
   - A future trained detector can use this layer to make decisions interpretable to utility engineers and managers.

5. Digital Twin Agent
   - The current digital twin simulates synthetic feeder behavior with NTL and operational disturbances.
   - A future extension can compare NTL and non-NTL counterfactual worlds against observed utility measurements.
   - Uses counterfactual reasoning to test whether the anomaly is better explained by NTL or by normal variation.

6. Coordination Agent
   - The current DeploymentReadinessEvaluator combines data quality, physics, explainability, federated-learning, and benchmark scores into a readiness report.
   - A future coordination layer can combine data confidence, physics consistency, anomaly strength, and digital-twin support into an NTL investigation score.
   - Operational alert delivery is a future workflow, not a current live utility function.

How it works:
- The current simulator generates controlled synthetic data for multiple feeder and meter conditions.
- The current federated-learning module simulates local client scoring and aggregation; it is not yet a deployed privacy system.
- The current output combines simulation statistics, data-quality checks, physics checks, explainability, and readiness scores.
- The proposed future detector would produce an explainable suspicion score rather than an unsupported yes/no claim.
- The framework is designed to support detection and investigation by showing why a synthetic event is suspicious.

Intended research benefits:
- Potentially better privacy protection through distributed learning
- Better explainability through evidence-based reporting
- Better physical consistency through feeder checks
- Potentially fewer false alarms after proper model evaluation
- Stronger utility trust and revenue-assurance support after operational validation
- Better support for operational decision-making after an approved deployment workflow exists

Simple research positioning:
The proposed contribution is a unified methodology for NTL research that combines federated-learning scaffolding, explainable analysis, physics-informed reasoning, and digital-twin validation into one auditable framework for hybrid distribution networks. The current contribution is the synthetic benchmark and readiness foundation; the trained detection method remains a separate research stage.

Current output:
Synthetic measurements, NTL event labels, feeder statistics, realism reports, readiness checks, and a deployment-readiness report.

Proposed future output:
An evaluated and explainable NTL investigation score produced by a trained detection method.

Possible output of the system:
- NTL suspicion score
- Evidence summary
- Physics consistency score
- Digital-twin support score
- Explanation for the utility team
